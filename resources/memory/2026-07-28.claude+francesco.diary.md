## 10:xx — A.1 — Supplier: migration + model + CRUD minimo

**Intenzione (prima di agire)**: primo passo di codice del gestionale. F. scrive, Claude tutor. Obiettivo A.1: entità `Supplier` con migration + model + CRUD minimo (lista/crea/mostra), coerente con §1-bis (entità nasce usabile).

**Fatto (F. scrive in autonomia, Claude tutor sui nodi)**
- Scaffold con `php artisan make:model Supplier -mc` (model+migration+controller). Lavoro a schermo splittato con `Product` come riferimento.
- **Migration**: campi `code` (poi `integer`+`unique`), `name`, `address`, `phone`. Scoperta `->unique()` via autocomplete.
- **Route**: scelta `Route::resource('suppliers', ...)->only([...])` (idiomatica, gradita) invece delle route a mano. Spiegate le 7 route convenzionali + trappola ordine `create`/`{id}` che `resource` gestisce da sé.
- **Controller**: `index` tutti (no flag active), `create`→view `createSupplier`, `store` stesso pattern di `Product`. Dettaglio inizialmente per `code`, poi passato a `id`.
- **Seeder** creato, popolato, registrato in `DatabaseSeeder`, lanciato.

**Nodi/trappole sciolti (5) — lezioni**
1. `Supplier::all()->orderBy(...)` → BadMethodCall: `all()` restituisce **Collection** (dati in memoria), `orderBy` è del **query builder**. Fix: `Supplier::orderBy('code','asc')->get()`. Regola: filtrare/ordinare → partire dal builder + `get()`, non `all()`.
2. `code` senza default → errore SQL `Field 'code' doesn't have a default value`, comparso 3 volte (seed, store, view create). Causa: `NOT NULL` senza default → qualcuno deve fornirlo. Intuizione di F.: "nei gestionali il code si autogenera" → tema di design (utente vs sistema).
3. Dettaglio 404 con ricerca per `code`: `findOrFail` cerca per **PK (`id`)**; passandogli un `code` cercava `id=<code>` → 404. Fix corretto di F.: usare `id` (in controller + view). Sfumatura: URL parlanti per `code` → eventuale route model binding su colonna, rimandato al Capitolo D (API).
4. Validazione `int` → regola inesistente; nome corretto **`integer`**.
5. `code` come **numero puro** (deciso da F.): allineati migration (`integer`+`unique`) e validazione (`integer`). Applicato con `php artisan migrate:fresh --seed` (droppa+ricrea+riseed; ok in dev, in prod si userebbe una migration di alter).

**Esito**: **A.1 chiuso e verificato** — `Supplier` con CRUD minimo (index ordinato per `code`, create/store, show per `id`), migration coerente, seeder funzionante. Roadmap A → **[1/6]**. Decisione `code` (mondo A = utente) annotata in PROGRAMMA §8.

Diagnosi per indizi (record si cancella? sì → `destroy` ok; URL finale = `/products.index` → redirect rotto). Mai il punto negli URL. Corretti 3 redirect ancora rotti (`ProductController` store/update, `SupplierController` store) → solo `/products` e `/suppliers`. Ricollaudato ok.
